# Transaction details and draft recovery

Build 0.18.0 adds read-only transaction details using the existing workspace-authorized endpoint. The view separates original transaction facts from current replayed gain, shows all returned revision evidence in the shared collection, and links retained promoted drafts to their posted entry and correction sources/replacements. Revision snapshots render as text; raw evidence is a secondary disclosure. Back retains the transaction collection's search, filters and preferences. Late responses are rejected after workspace/editor/navigation changes.

New entries use separate Save draft and Post transaction actions. Save draft is the default for implicit submission. Posting is exposed only to owners/managers; contributors can save drafts. Existing draft editing uses Save draft changes, with promotion kept as its separate revision-checked operation. Posted history remains immutable; no canceled lifecycle or correction eligibility changes are introduced.

Editing fetches the current authorized transaction before opening and updates its cached collection row. Validation and posting failures retain the entered values and display feedback beside the form. Insufficient-cash feedback explains saving a draft and recording earlier funding/opening balances. Revision conflicts retain text and expose Reload latest transaction; reload uses the existing discard confirmation and cannot silently overwrite unsaved input. Native required/pattern errors are surfaced beside the form; the API still returns general validation messages rather than a structured field-error map.

No new runtime dependency, financial arithmetic, SQL migration or backend mutation is added. Schema remains 8. Detail deep links, scalable server query/history contracts, correction eligibility/action UX, broader accessibility/performance acceptance and structured per-field server errors remain pending. Full production-host and restore gates remain required.

Transaction browser fixtures cover exact draft values, explicit actions, server validation errors, stale revision retention, rejected/accepted reload, promotion source links, revision viewing, immutable posted details, insufficient-cash recovery and complete cursor search. Opening cash/lots followed by a posted sale, Journal desktop/mobile workflows, 11 private-media HTTP cases and all eight admin sections at 360/768/1440 pixels passed. Detail/revision evidence was separately checked on desktop/mobile and visually reviewed; temporary sessions, screenshots and private bytes are excluded from Git and packaging.
