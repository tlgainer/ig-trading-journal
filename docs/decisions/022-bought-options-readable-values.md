# Bought options and readable trading values

Build 0.22.0 adds private bought call/put scenarios for selling at an entered option premium or calculating expiration intrinsic payoff. Inputs distinguish option premium from underlying stock price, require positive whole contract count and allow the actual contract multiplier. Entry and exit/settlement fee amounts are deducted explicitly. Starting capital is entry premium value plus entry fees; payoff is separate from net profit and return. Sold options, pre-expiry valuation models, spreads, exercise/assignment and resulting stock/cash accounting remain outside scope. No ledger event or account mutation is created.

Calculator labels now use entry price, take-profit/exit price, stop-loss price and starting capital where those terms describe the input. Risk budget remains clearly labeled as maximum acceptable loss. The long-risk form now accepts an actual stop-loss price below entry. The API retains its original stop-distance contract for older clients, accepts either price or distance and rejects supplying both. Short sizing continues using an actual stop above entry. Starting capital, notional exposure and margin remain distinct.

Spot, long-risk and equivalent-unit outputs now use the existing shared decimal-string formatter. Transactions, transaction detail financial facts, report observations and reports also use it. Redundant trailing zeros disappear; amounts retain at least two decimal places and quantities trim redundant fractional zeros. Significant precision is preserved, including tiny values, large exact decimals, crypto quantities and FX rates. No binary floats or rounding of stored values is introduced. Raw revision evidence and exports stay exact. Holdings and Transactions retain their shared table layouts; old cards indicate an earlier installed build or cached assets.

Schema remains 8; no SQL migration is needed. All eight bundled SQL files remain packaged. Personal setup notes and temporary browser/database/session artifacts are excluded from Git and the package.

Validation: 46 unit and 84 disposable WordPress/MySQL integration checks passed, including option gains/losses, call/put intrinsic payoff, fees, adjusted multiplier, invalid contracts, workspace authorization, non-posting behavior and old/new long-risk inputs. PHP/JavaScript syntax, Composer coding standards and six REST URL checks passed. Browser fixtures exercise bought options and the long-risk screenshot example on desktop/mobile, Holdings pagination/formatting, Transactions revision/promotion/details, manual reports, research/spot scenarios and all eight admin sections. Actual-host, complete accessibility, sustained performance and restore acceptance remain separate gates.
