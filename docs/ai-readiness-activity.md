# Owner AI readiness and saved request activity

Settings > AI summary settings now shows saved setup readiness: server credential preparation, exact selected model, current reviewed model/pricing records, current reviewed counting-access/cost records, server switch, workspace consent and budget pause state. These are local checks of saved settings/server evidence, not authenticated discovery or independent account verification. No model prices, API keys, credential fingerprints or server evidence are returned. Generation controls remain unavailable even when preparation records are current.

Expand **Saved AI request activity** to read the workspace's saved requests. The existing scoped collection pattern loads all cursor pages before enabling local search, sorting, column preferences and density. Search covers request metadata for that workspace only; it does not cover summary text or other workspaces. Reload reads stored state without counting, generating, resending, cancelling or publishing. It preserves unsaved model, budget and consent fields. Workspace changes clear previous history and discard stale responses; failed reads clear the table and support an explicit reload.

The owner-only GET `/workspaces/{id}/ai-requests` route accepts the existing bounded `after`/`limit` cursor contract (limit 1-100). Request/event relationships and lookups are workspace scoped. Its fixed projection contains request ID, nullable approval ID, captured model, UTC creation date, original decimal cost ceiling, latest state and nullable usage charge estimate. It excludes request keys, actor IDs, credential digests, pricing JSON, manifests, prompts, evidence text, raw provider bodies and usage JSON. Existing HTTPS, authentication, explicit membership and no-store protections apply; managers/viewers cannot read it.

States are deliberately distinct: reserved means not sent; delivery claimed does not prove delivery completed; uncertain delivery retains its reservation; usage settled does not prove usable or published review output. Cancelled requests show no charge. Legacy unbound requests are labelled as such and cannot gain fabricated approval provenance through this screen. Figures are plugin accounting estimates, not an OpenAI billing statement. The table is read-only and provides no retry/delivery or recovery controls.
